# Codex 用量管家

这个插件把本机 `~/.codex/sessions` 里的会话日志解析成额度视图：周额度、5 小时窗口、每日消耗、按天建议用量。全部离线完成，不联网、不上传。

## 先想清楚用户问的是哪一类问题

| 用户的问题 | 该调用的工具 |
| --- | --- |
| "我还剩多少额度 / 什么时候刷新" | `usage_status` |
| "今天还能用多少 / 怎么规划今天的用量" | `daily_plan` |
| "最近几天用了多少 / 我是不是用太猛" | `usage_history` |
| "给我一份用量报告，写到文件" | `write_usage_report` |
| "打开一个看得见的仪表盘" | `open_dashboard` |
| "在桌面上放个悬浮表盘 / 我要一直看到余量" | `show_dial`（收起用 `hide_dial`） |
| "帮我改预留缓冲 / 时区 / 端口" | `configure`（改之前先跟用户确认数值） |

一次回答通常只需要一个工具：先 `daily_plan`（它包含 status 的关键数字），只有用户只想看余额时才用 `usage_status`。

## 怎么读结果

- `basis: "live"` — 额度快照新鲜，百分比就是真实读数。
- `basis: "estimated"` — 快照已过期，已用额度是按之后记录到的 token 消耗**推算**的。回答时必须说清"这是估算值"，并给出快照时间。
- `basis: "history"` — 完全没有额度快照，只能按最近 7 天日均消耗给建议，不是真实余额。
- `snapshot.freshness` — `live`（15 分钟内）/ `fresh`（4 小时）/ `stale`（1 天）/ `old` / `veryold`。超过 1 天就要提醒用户"打开 Codex 随便聊一轮就能刷新读数"。
- `tokensPerPct` — 1% 周额度约等于多少 token，由历史数据标定；`calibration.method === "fallback"` 说明样本不足，是默认估值。
- `plan.todayPace` / `plan.weeklyPace` — `over` 用得太快、`tight` 略快、`ok` 正常、`roomy` 还有余量。

## 回答格式

先给一行结论，再给数字，最后给一条可执行建议。例如：

> 本周还剩 100%（≈305M tokens），12-01 17:08 重置；今天还能用约 8.5M tokens。快照是 5 天前的，剩余量按之后的消耗推算，属估算。

不要输出大段原始 JSON，也不要把整张历史表贴出来（除非用户要）。数字保留一位小数就够。

## 注意

- `open_dashboard` 会在本机起一个 `127.0.0.1` 的小服务（默认 8787 起）并返回 URL；只有用户明确想要可视化界面时才调用，不要每次问答都开。
- `show_dial` 启动 Windows 像素猫咪，自动读取 Codex 输入框位置；停步气泡显示本周与 5 小时余量，右键详情在头顶展开。猫咪不是全局置顶窗口，跟随 Codex 显隐并在 Codex 关闭后退出。默认每 30 秒刷新，已运行时不重复启动。关闭用 `hide_dial`，重启传 `restart: true`。
- 报告默认写到 `~/.codex/usage-coach/reports/`，只有用户要求时写文件。
- 所有工具都是只读的（除 `configure` 会改配置、`write_usage_report` / `open_dashboard` / `show_dial` 会写文件与起进程），不需要为读数据征求许可。
- 如果工具返回 `isError: true`，把 `content[0].text` 里的原因直接告诉用户，不要自己编数字。
